# iter-21 · K8s 邮件告警验证（阿里云 JDK 镜像 + Secret/ConfigMap）

- **日期**：2026-10-22
- **分支**：`feature/k8s-email-demo` → `master`
- **类型**：feat（部署验证 + 示例产物）
- **关联**：journal/2026-10-22、iter-18/20

## 1. 背景

用户提供国内可拉取的公开镜像 `registry.aliyuncs.com/pkyit/java:jdk17-font`，
要求在真实 k8s 集群（3 master + 3 node，Anolis OS）中验证邮件提醒，凭据不得入库。

## 2. 问题点（含证据）

| # | 问题 | 证据 | 处理 |
| --- | --- | --- | --- |
| 1 | sample 打出的 jar 只有 8 KB，不能 `java -jar` | `mvn package` 后 `target/*.jar` 8845 B | 父 POM 只在 pluginManagement 管理版本，未绑定 `repackage`；在 sample 增加 execution |
| 2 | 27 MB fat jar 需要进入容器，但没有自建镜像仓库凭据 | 用户只给了公开**拉取**镜像 | 冒烟用 `kubectl cp` 拷 jar；同时提供 `Dockerfile` 供生产构建自有镜像 |
| 3 | 凭据不能写进 ConfigMap/仓库 | 公开仓库硬规则 | Pod 通过 `secretKeyRef` 注入 `NOTIFYX_SMTP_USER/PASS`；ConfigMap 里用 `${...}` 占位 |
| 4 | 容器内没有 `/app` 目录，`kubectl cp` 目标路径失败 | `cp` 前目标父目录不存在 | 先 `exec mkdir -p /app` |
| 5 | 应用配置需要覆盖 classpath 里的 dev 配置 | sample 默认 `channels: [log]` | ConfigMap 挂载 `/config/application.yml`，启动加 `--spring.config.additional-location=file:/config/` |

## 3. 改动点

- `notifyx-sample/pom.xml`：增加 `spring-boot-maven-plugin` 的 `repackage` execution，
  产物变为可执行 fat jar（约 26 MB）。
- 新增 `deploy/k8s/`：
  - `namespace.yaml`、`configmap.yaml`（邮件渠道 + 场景 + 模板，凭据占位）；
  - `secret.example.yaml`（仅占位）；`pod.yaml`（阿里云 JDK 镜像、Secret 环境变量、ConfigMap 挂载）；
  - `Dockerfile`（生产镜像示例）；`README.md`（构建 → Secret → Pod → cp → 触发 → 清理）。
- README 增加 k8s 验证入口。
