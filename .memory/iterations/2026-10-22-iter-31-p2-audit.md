## 1. 审计范围

本轮持续目标：**T1 跨实例聚合（Redis）、JDBC store（审计/补偿）、MQ 总线（Kafka/RabbitMQ）与 consumer**。
以下逐项给出实现与验证证据。

| 目标项 | 实现 | 真实中间件验证 |
| --- | --- | --- |
| T1 跨实例聚合 | `RedisAggregator`（Hash 计数 + `SET NX` 抢锁），iter-23 | k8s Redis 6.2.23：两实例并发只发一条摘要 |
| JDBC store | `JdbcAuditRecorder`、`JdbcFailureStore`（CAS/requeue）、`JdbcAuditRetention`，iter-24/30 | 真实 MySQL 8.0.46、PostgreSQL 16.15：审计写入、失败记录 CRUD、保留期 |
| Kafka 总线 | `notifyx-bus-kafka`（key=dedupeKey、acks=all、幂等），iter-25 | k8s Kafka 4.3.1：发布→消费同一报文 |
| RabbitMQ 总线 | `notifyx-bus-rabbitmq`（durable、persistent、confirm），iter-28 | k8s RabbitMQ 3.13.0：publish→basicGet |
| Consumer | `notifyx-consumer`（transport=kafka/rabbitmq、三档幂等、完整责任链），iter-26/27/29 | 真实 Kafka/RabbitMQ：两条相同 envelope 只发一次通知 |
